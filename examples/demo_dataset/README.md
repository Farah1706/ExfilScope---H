# ExfilScope demonstration dataset

**Everything in this folder is fictional.** Calderbrook Regional Services Authority, the
Calderbrook Citizen Services Portal, their departments, people, accounts, references and
domains (`*.calderbrook.example`) do not exist. Registered protected values are invalid
demonstration strings that authenticate to nothing.

This folder holds the fictional records used in the ExfilScope demonstrations, in a readable
form, and lists the files the running system reads. Those files stay in their original places.

| File | What it is |
|---|---|
| `documents/*.json` | Six fictional organisational records: an operations status bulletin, a billing gateway integration record, a quarterly operations review, a customer account service note, a staff newsletter and a residency-renewal status notice |
| `document_manifest.json` | Each record's source reference, role in the scenarios and registered IDs, plus the SHA-256 of the frozen inputs below |
| `protected_registry.json` | The three registered value categories by ID and source. **No values** |
| `scenario_catalog.json` | The nine Scenario Lab situations, their engines and the records each draws on. Generated by `python -m webapp.dataset` from `webapp/scenarios.py` |

## Frozen inputs (read by the system, never edited)

| Path | Read by |
|---|---|
| `examples/phase2/documents.json` | The agent worker's retriever (corpus v1, five chunks) |
| `examples/registry.json` | The gateway, the platform's privacy checks and the lab harness |
| `examples/policy.json` | The gateway policy example (`example-policy-2`); the lab harness builds the equivalent `lab-policy-2` in memory |

These files are bound by the research freezes, so they keep their original wording and
identifiers. The manifest records their SHA-256 values; the platform shows whether each still
matches, and `webapp/tests/test_workspaces.py` fails if one changes. The frozen Experiment 1
inputs and evidence are custodian material under `artifacts/` and are not part of this folder.

## Versions

- v1 is the frozen corpus and registry above, unchanged since the research runs.
- v2 (this folder) adds the readable presentation records, the manifest and the indexes.
  Each record quotes its v1 corpus chunk as the "retrievable excerpt", with registered values
  replaced by their registry ID. v2 changes nothing the agent retrieves or the gateway checks.

Stable internal identifiers (`DOC_001:chunk_1`, `SECRET_001`, ...) are kept because source
attribution, registry matching and the recorded evidence depend on them.

## How the records relate to the scenarios

- The agent modes (live Qwen3 and the deterministic stub) retrieve from corpus v1. The
  routine task uses the status bulletin; the confidential-report and restricted-record tasks
  use the billing gateway integration record. The staff newsletter is an unrelated record the
  retriever must pass over.
- The controlled laboratory builds its own request bodies. Harmless bodies are generated
  (`harmless-<case>`); where a situation needs a registered value, the harness picks
  SECRET_001, SECRET_002 or SECRET_003 by case number.
- The Government Trust extension sends the fixed RS-1042 notice body defined in
  `webapp/trust/demo.py`, shown here as the residency-renewal notice.

## Viewing it

Open **Scenario Lab → Synthetic data explorer** in the platform. It shows each record, its
v1 excerpt with registered values masked, the scenarios that use it and the integrity of the
frozen inputs. The service never sends a registered value to the browser; forensic evidence
(Ledger A and Ledger B) keeps only registry IDs, source references and keyed body fingerprints.
